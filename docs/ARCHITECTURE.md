# v5 架构与职责

```text
用户描述 + 当前规则 + 简短对话 + 字段可用性
    → 本地明确语法编译 / DeepSeek 结构化提案
    → schema、分组、并集语义、边界与冲突检查
    → 澄清或提案：变更列表 / 缺失 / 预计名单差异
    → 用户确认并筛选 → 同步更新编辑区与执行计划 → 确定性筛选 → 逐条件解释
```

## 数据层

`lib/roster.ts` 仅存公开证券标识、名称和行业；`lib/universe.ts` 存人工研究题材及业务依据。`lib/providers/fuyao.ts` 封装授权、超时、重试与响应校验；`lib/official-data.ts` 协调交易日、披露期、批量报价/估值、现金流和派生指标。`lib/market-data.ts` 与 `lib/indicators.ts` 是确定性行情计算，不调用公开替代源。

`GET /api/market-status` 先确认官方批次与完整交易日；`GET /api/stock-data` 返回该日单股字段、来源和回执。前端有限并发加载50只、展示进度，逐股失败保留未知。`GET /api/institution-data` 取得20个交易日完整机构披露，再计算5/20日计数。`POST /api/stock-evidence` 用扶摇复核或 iFinD 查询相同报告期，独立返回证据，不自动改结果。

缓存是进程内短期优化，不是持久存储。不同 Worker 实例不共享缓存，首次全量加载仍需供应商调用。初始化上下文失败时保留原数据与时间；成功刷新后数据版本改变。刷新会以新批次重新计算已执行条件的结果。

## 规则层

`Plan` 两组条件分别存放价值与基本面和波段模型，内部兼容键为 fundamental/trend。`sectors` 是统一的行业或题材并集；与数值规则AND。未验证指标产生 unknown。模型只输出规则，执行名单和解释由 `lib/screener.ts` 计算。

重复条件、上下限矛盾、有限域越界由代码识别。`lib/intent-workflow.ts` 提供规则版本指纹、两套规则整体冲突检查、可用字段清单、明确均线边界校验。该指纹用于客户端防止误用旧提案，不是安全签名。

## AI层

`lib/intent.ts` 负责明确语法、别名、增量修改、多轮澄清事务；复杂表达进入 DeepSeek。`app/api/interpret/route.ts` 校验输入、压缩历史、调用模型、校验输出并附阶段记录。模型调用有限超时；接口异常不改变规则。取消按钮停止客户端等待，不保证已送出的上游推理立即停止。

部分语义可确定性验证，如板块OR和“站上”严格边界；无法声称通用语义证明。模型表达和条件预览都保留，人确认后才执行。没有让模型凭空补财务/行情。

## 界面与审计

`app/page.tsx` 管理编辑/执行双状态、预览、撤销、比较、保存、来源详情和导出。`DataPanel` 统一解释官方来源、时间、口径、异常和待验证指标。每次执行记录时间、规则版本、数据版本、覆盖率、最近采用的AI请求ID；最多保留当前会话20次执行，导出可供复核。

## 安全与部署

密钥仅服务端环境变量；原始授权金融回执只在运行时返回给站点访问者，不静态打包。站点已开放公开链接访问；供应商密钥仍由服务端保管。生产 Worker 禁止模块初始化时生成随机值：静态模板使用稳定ID，用户操作/请求中才生成动态ID。CI包含冷启动回归，防止本地正常而生产模块加载失败。
